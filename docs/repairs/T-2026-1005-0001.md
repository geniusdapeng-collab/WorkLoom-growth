# T-2026-1005-0001：公开视频制作入口消费当前原生计划

原先 `film.start` 接受调用方 `document.shots`，公开 `full-chain-film.mts` 又能直接调用模型。代理因此可以手写分镜，跳过营销/叙事策划与前置系统检查，最后只跑部分后期。本任务将公开入口收口为客户意图和档案身份 → 正式工作室预生产 → 服务读取当前原生计划 → 固定工位的一次完整制作。

## 行为与接口

- `FilmServiceClient.prepare({intent, characterId?, productId?, platform?, route?})` 调用既有 `video.studio.start`。服务先从客户确认的商品档案解析商品锚点，再走既有分流器。客户端不传剧本、分镜、提示词、事实包、路径或模型密钥。
- `video.film.plan({projectId})` 读取当前 PG 预生产终态、作用域、各门证据、场景策略、营销事实包和原生交接稿。返回当前来源三个标识、每镜时长与提示词摘要、完整步骤、预计预占和 `humanAcceptance=final-film-only`。
- `video.film.start` 只接受服务返回的 `sourceVersion`，在项目租约内重新核实当前来源，再冻结原生稿。镜号、顺序、时长、完整提示词和结构字段不得由调用方改写。
- 公开 CLI 只提供 `--prepare`、`--project --plan`、`--project` 与原作业状态查询；付费制作不接受 `--shots`、片单路径、阶段裁剪、post-only、绕行批准或自动重渲。诊断 dry-run 仍不能调用付费模型。
- 每次正式作业固定执行 cine-kb、continuity、micromotion、spec、plates、material-gen、videos、voice、compose、color、subtitle、danmaku、bgm、cover、mux、master、deliver。具体镜头不适用的步骤由冻结来源和真实账本决定，不能靠调用方省略阶段。
- 相同原生来源在 running、finished、failed 或 interrupted 状态后都不能认领第二个付费作业。项目级事务锁同时约束并发认领；超时和未知回执只查原作业，不重发。

## 原生策划与档案交接

工作室从本次供应商原生完整提示词记录恢复最终摘要中省略的字段，不重写提示词。内部交接编译器消费本次完整剧本/分镜/提示词，派生钩子、场景档案及逐镜物理关系；拒绝增删镜头、改台词、改时长或改提示词。编译和完整稿系统检查失败时停在渲染之前，没有手写替代或模型降级批准。

人物与商品只能通过系统档案 ID 选择。已有验收图片由原生定妆工位登记真实复用回执，逐文件检查摘要；真人参考素材来自当前授权主档。商品事实包来自客户确认档案原文与图片摘要，仍经过本次宿主 G1 和最终事实审核。人类仅验收最终成片，中间系统检查保留完整文本/文件摘要证据。租户显式收紧的围栏和预算限制仍生效。

供应商调用前父服务核对镜头时长、真人参考素材，并审核完整编译请求与冻结稿。渲染后的审美 review 可以关闭；该开关不能关闭渲染前内容与来源检查。图片生成未知结果、网络失败或畸形成功回执不自动重试。

## 验证与边界

基线 `52a600e3f6a9f94c0ea67b4be5f5d713e5d00ddd` 的实际行为反例：旧客户端把手写 document 发往 fetch 并接收成功回执，拒绝断言失败。修复后的专用 Node 断言覆盖公开客户端、服务、CLI、17 个步骤逐项缺失、客户产物注入与只提交意图/档案身份的正常路径。原生来源/场景交接、人物/商品复用、营销来源、工作室与完整后期账本另有回归。

独立正式 Electron 载荷已通过官方 Node/PG/NATS 摘要与载荷自检，并由官方 bootstrap 在专属目录启动；活库台账测试覆盖并发和四种终态的重复提交保护。当前文档记录机制变更，不把载荷启动或模型替身测试等同实际成片效果；真实制作与发布回执继续以任务台账为准。

没有新增数据库迁移：去重身份保存在既有 `film_jobs.options.nativeSourceKey`，读取仍限定当前租户、工作区和项目。MCD 排查范围仅视频制作入口，未宣称全仓 RDAS 276 项验收。回滚使用 revert 本任务提交，保留追加账本、档案、已接受的平台任务及媒体，不自动重新渲染。
